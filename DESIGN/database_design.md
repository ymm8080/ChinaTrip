# 数据库设计 — ChinaTrip

> 版本：v1.17 ｜ 更新：2026-10-27 ｜ 纯设计口径：不含代码、文件路径与命令 ｜ 事实来源：应用数据模型、迁移史与数据管线设计（2026-10-23 快照）
>
> 覆盖：PostgreSQL 生产 schema 21 表（含 v2.5 新增 restaurants / weather_reports / 评论域 poi_reviews·poi_stats / payments 表与 pois 15 列扩容）+ 本机 SQLite 状态库 6 表；数据源 × 刷新矩阵（优先级 / 链序 / 频率 / 时机 / 模式）。

---

## 1. 双库关系（谁是什么真相）

| 存储 | 定位 | 说明 |
| --- | --- | --- |
| **PostgreSQL / PostGIS**（迁移管理） | 生产 schema 真相 | 参考数据（POI/餐厅/营业时间）+ 行程正式库 + 交易域 + 账号。各区独立实例，schema 一套 |
| **本机 SQLite 状态库** | 单机服务 write-through 态 | 进程内字典是热路径，每次变更落一行；启动时全量加载。坏行跳过告警，不拖垮服务 |

补充：POI 详情存储在数据库不可达时降级进程内存（300 秒重试闩），规划永不因库挂而停。全量测试会写真实状态库（已知现状）。

## 2. 实体关系概览（按域）

- **参考数据域**：pois 一头连 poi_hours（营业时间规则）与 itinerary_items（行程站点引用）、trip_items（心愿条目关联）；restaurants 为 v2.5 新增的平行餐厅库。
- **行程域**：itineraries 为根，下挂 itinerary_snapshots（不可变快照）、itinerary_days（逐天宿营地）、intercity_transfers（跨城段）、itinerary_items（逐天站点）、execution_events（执行轨迹）。
- **行程中心域**：trip_items（三态单一事实源）、user_profiles（画像）、link_history（链接历史），均锚定用户与行程。
- **交易域**：action_handoffs（预订漏斗）为根，entitlements 关联用户与行程，iap_transactions 挂权益，paywall_rules 独立远程配置。
- **账号域**：users 为全局锚。

关键连线：行程站点与心愿条目通过 POI 的 UUID 引用主库——UUID 永不变，管线刷新不打断引用；心愿条目可关联预订漏斗记录（booking_id）。

## 4. 表详解

### 4.1 参考数据域

#### pois — POI 主库（v2.5 后 24 列）

稳定键「来源 + 来源方主键」唯一，UUID 主键**永不变**——管线刷新不打断行程引用。

| 列 | 类型 | 说明 |
| --- | --- | --- |
| id | UUID 主键 | 永不变 |
| source / source_poi_id | 短文本 | 稳定键（amap / ctrip / chinatravel / osm / wikidata…），联合唯一 |
| city | 短文本 | 城市索引 |
| name_zh / name_en | 短文本 | 中文名入库套城市别名表 |
| category | 短文本 | attraction / food / … |
| status | 短文本，默认 active | 存活性（回源链剔除关店） |
| location | 地理点（4326） | **GCJ-02 主存**（高德系）；空间索引 |
| wgs84_location | 地理点（4326） | v1.7 双坐标副本，境外渲染防漂移；入库成对写 |
| address | 短文本 | v2.4.4 |
| opening_hours | 中文本 | v2.4.4 |
| hours_source / hours_updated_at | 短文本 / 时间戳 | 溯源 ctrip / amap_v5_detail / amap_v5_search；超 24 小时判过期 |
| phone / website | 短文本 | v2.5 |
| rating / rating_source | 数值(3,1) / 短文本 | v2.5；评分只是排序信号非事实断言 |
| tags / tags_source | JSONB / 短文本 | v2.5 品质标签：michelin / bib_gourmand / black_pearl（含钻级）/ unesco / 国家一/二/三级博物馆（museum1/2/3 名单行） |
| intro / intro_source | 长文本 / 短文本 | v2.5，来源维基百科系；已有不覆盖，随回源周期更新 |
| photos / photos_source | JSONB / 短文本 | v2.5，维基共享 800px |
| best_visit_time | 短文本，默认 any | v2.5：morning / afternoon / evening / sunset / sunrise / any |
| best_visit_time_source | 短文本 | v2.5 三层：heuristic / llm / ctrip |
| suggested_duration_min | 整数 | v2.5 建议游玩时长 |
| origin | 短文本 | v2.5 初始发现渠道（来源升级为回源真相后保留出身） |
| updated_at | 时间戳 | 自动 |

**v2.5 铁律**：外部源仅写骨架（名称/坐标/类别）；时间敏感字段（营业时间/门票/时长）只信高德/携程回源链；每个富化字段带溯源列。

#### restaurants — 餐厅独立表（v2.5 新增）

产品拍板不再以「pois 的 food 类目」复用。骨架列与 pois 同构（稳定键 / 城市 / 中英名 / 存活态 / 双坐标 / 地址 / 营业时间三件套 / 电话 / 网站 / 评分 / 标签 / 简介 / 照片 / 出身 / 更新时间，均带溯源），差异：

- 增 **cuisine**（菜系）与 **avg_cost**（人均，数值两位）
- **无** best_visit_time 与 suggested_duration_min
- 同款约束：稳定键唯一 + 空间索引 + 城市索引

#### poi_hours — 营业时间规则表

主键 ｜ POI 外键 ｜ 规则类型（短文本）｜ 规则体 JSONB（节假日例外 / 临时闭园等，行前 30 天抓取）。

#### weather_reports — 城市天气快照（v2.5 新增）

数据源双轨（2026-10-24 起）：① 高德天气 API（**上游 = 中国气象局**）——实况 + 3~4 天预报，0-3 天权威口径，按 adcode 查询与 POI 库同键；② Open-Meteo（TREK 方案第二轨，免 key 无配额）——14 天逐日预报（WMO 码转中文），补 4-14 天，payload 与高德 forecast 同构。**latest-wins**：每「来源 + adcode + kind」仅存最新一行，不堆历史——report_time 是上游侧数据时间（高德实况每小时更、预报每日约 8/11/18 时三更新），fetched_at 是本侧拉取时间，两者对照即新鲜度口径。**清理**：fetched_at 超 7 天的行由抓取作业末尾删除（不再抓取的城市滞留数据）。

| 列 | 类型 | 说明 |
| --- | --- | --- |
| id | UUID 主键 | — |
| source / adcode / kind | 短文本 | 联合唯一稳定键；source ∈ amap / open-meteo；kind ∈ live / forecast / forecast14（CHECK 约束，0008 放开） |
| city | 短文本 | 上游返回的城市名，城市索引 |
| report_time | 时间戳 | 上游侧数据时间（判过期用它，不用 fetched_at；Open-Meteo 无此字段存 NULL） |
| payload | JSONB | 实况：天气/气温/风向风级/湿度；高德预报：今日起最多 4 天；forecast14：14 天逐日 casts（date/天气文本/高低温），两源同构 |
| fetched_at | 时间戳 | 本侧拉取时间，自动；超 7 天被清理 |

配额约束（高德）：个人 key 约 100 次/日（以高德控制台为准），每城每班 2 次调用（实况+预报）——**默认只抓行程涉及城市**，40 城全量 3 班/日 = 240 次会超配额，仅限手动单次。Open-Meteo 无配额压力（免费档 1 万次/日），**每次运行固定全量 40 主要城市**（产品口径：主要城市 × 14 天全覆盖，覆盖全部 POI/餐厅所在城市）。

### 4.2 行程域

#### itineraries — 行程工作副本

UUID 主键 ｜ 用户外键（可空）｜ 城市数组 ｜ 标题 ｜ 工作版本号（默认 1，溯源用）｜ 当前执行快照指针（**无外键**——与快照表循环依赖）｜ 状态（默认草稿）｜ 创建 / 更新时间。

#### itinerary_snapshots — 不可变快照

UUID 主键 ｜ 行程外键 ｜ 名称 ｜ 备注 ｜ 同步版本号（对齐触发时的工作版本）｜ 创建时间。**只增不改**；当前执行快照指针指向执行版。

#### itinerary_days / intercity_transfers / itinerary_items

| 表 | 唯一约束 | 关键列 |
| --- | --- | --- |
| itinerary_days | 行程 + 天 + 快照 唯一 | 宿营城市 |
| intercity_transfers | 行程 + 天 + 序 + 快照 唯一 | 出发 / 到达城市、方式 |
| itinerary_items | （无唯一约束） | 天、POI 外键（可空）、位置序、起止时刻（可空）、草稿标记（默认真） |

三表都带快照外键（可空）——**空 = 工作副本**，非空 = 冻结在对应快照里。快照恢复 = 按快照读回。

#### execution_events — 执行轨迹（分区表）

UUID + 时间戳组成联合主键（分区键必须入主键）；行程外键、事件类型、JSONB 载荷。真实分区在迁移 DDL 中定义；轨迹敏感：加密、30 天保留、双人审批（设计约束）。

## 6. 数据源 × 刷新矩阵（参考数据域管线）

**总原则（DIFF UPDATE）：一切周期刷新只处理差异，绝不全表重写。** 爬源走变更检测三层（ETag + 哈希 + LLM），判定变更后仅 upsert 差异行；上游 dump 类（OSM）按增量差异消费；回源按过期检查（无值或超 24 小时才刷）；回填按只填空。全量重跑仅限冷启动与灾难恢复两个场景。

### 6.1 优先级分层（真相归属）

| 层 | 角色 | 源 | 对表 |
| --- | --- | --- | --- |
| **L0 回源真相** | 存活性与详情唯一真相 | 高德（v5 详情、关键词搜索）、携程 sight 页、POI 官网公告 | pois / restaurants / poi_hours |
| **L1 权威校准** | 必保白名单 + 查全率告警 | 文旅部 5A 名录 373 处、UNESCO 59 处、国家一/二/三级博物馆名单（一级 327 家官方口径，剔除革命/政治/战争/领袖/现代人物纪念类 64 家 + 区县级 17 家后 246 家在库（滕州市汉画像石馆经用户拍板回灌）；另收录国家重点美术馆 12 行（artmuseum）+ 浦东美术馆（未评级无标签）+ 国家二级博物馆 344 行（museum2，产品口径过滤后，见 v1.14/v1.15）+ 策展知名美术馆 28 行（curated）） | pois |
| **L2 骨架种子** | 只写名称+坐标+类别 | ChinaTravel 3,413（一次性）、OSM 日更、FSQ（可选后置） | pois / restaurants |
| **L3 回填/标签** | 富化字段 | 维基百科系（简介/照片）、米其林、黑珍珠、best_visit 三层 | pois |
| **L4 兜底末位** | 只补全源未收录 | Tripadvisor 内容 API（审批实测中，未上线） | pois |

**铁律：L0 高于其余一切**——任何层的数据入库前 / 首轮回填必经 L0 校验；外部源只管「发现」，真相归回源链。

### 6.2 矩阵总表

**时机派生规则（实测+1）**：**定点发布源**（月更/年度）拉取时机 = 上游实测落地日 + 1，无固定落地日者按最晚观测留余量；**日更源不适用「日 +1」——每天在实测发布窗口之后定时补当日更新**（OSM = 06:30）。计划数与实测冲突时以实测为准。下列时机均括注实测日期与方法，供复测校准。

### 6.3 链序（同一字段多源时的取值顺序）

- **营业时间 / 门票 / 时长**：携程 sight（先）→ 高德 v5 详情（有 ID）→ 高德 v5 关键词搜索（兜底）→ POI 官网（节假日例外入规则表）
- **best_visit_time**：类别启发式 → LLM 常识 → 携程回源校验（后者覆盖前者，溯源记最终层级）
- **简介 / 照片**：维基数据 → 中文维基百科摘要 → 维基共享图像；只填空
- **评分 / 人均**：高德 / 携程回源独占（外部源一概不采信）

### 6.5 非参考数据域（无批刷）

- **行程域**：应用写入（规划 / 保存 / 快照 / 恢复）；无定时刷新。快照 append-only；执行轨迹分区滚动 30 天。
- **行程中心域**：用户 / Agent 动作驱动，即时写；无批刷。条目删除回写 unwanted 分组。
- **交易域**：漏斗状态机事件驱动（opened → … → settled）；付费点规则远程配置人工改。
- **账号域**：用户动作驱动；验证码按过期时间 TTL 失效，发送日志按小时窗口计数。

## 7. 设计约定（铁律速查）

1. **稳定键 upsert**：「来源 + 来源方主键」唯一，UUID 永不变——多源导入 / 回源刷新不打断行程引用。
2. **回源铁律（v2.5）**：外部源只写骨架；营业时间 / 门票 / 时长只信高德 / 携程回源链；每富化字段带溯源列。
3. **双坐标**：GCJ-02 主存 + WGS84 副本，入库成对写。
4. **快照不可变**：快照外键空 = 工作副本；快照行只增不改；工作版本号溯源。
5. **全表更新时间**；日期 ISO 8601；金额人民币（人均两位小数）。
6. **数据驻留**：用户数据只落本区；参考数据 CN 主库单向复制海外（白名单）。
7. **许可隔离**：高德数据与 OSM 数据物理分库（开源许可署名义务只随库本体再分发触发）。
8. **执行轨迹**分区 + 30 天 + 加密 + 双人审批。
9. **降级不阻塞**：POI 详情库不可达 → 内存降级 300 秒闩；状态库坏行跳过。
