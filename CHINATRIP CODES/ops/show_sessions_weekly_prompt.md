# 每周日晚演出场次刷新 — 自动化注册词

> 本文件供新对话注册定时自动化用（定时会话内不能创建定时任务）。
> Cron：`0 21 * * 0`（每周日 21:00，本地时间），recurring=true，无 maxRuns。
> 标题：每周日晚21:00刷新演出场次时间

## Prompt（原样粘贴）

执行演出场次时间周刷新（ChinaTrip 项目，工作目录 D:\CHINATRIP\CHINATRIP CODES）。

任务：刷新 DESIGN/POIS DATASOURCE/04_演艺演出_主要旅游城市.csv 的 session_time 列（50 行演出），并同步 DB pois 表 source='show' 行的 opening_hours。

步骤：
1. 读 CSV 当前 session_time 值，挑出需要复核的行：值里含「以当日公告为准」「随排期」的行优先；「旺季加场」类行次之；千古情系列（宋城/三亚/西安/丽江等 13 家）因场次随季节变动大，每周至少抽 3 家复核；另外每次检查《吉祥颂》是否复演（2026-01-20 起暂停中）。
2. 用 WebSearch 逐场核实当日典型场次时间（如「驼铃传奇 场次时间」）；每次搜索 4-5 个并行，若搜索接口持续限流则如实报告并结束本轮，等待下周（勿硬重试到卡死）。已核过且无变化迹象的行不要为改而改。
3. 把确认变化的行（只在有搜索依据时才改值）写进 ops/show_sessions_updates.json，格式 {"name_zh": "session_time"}。铁律：session_time 必须以这些前缀之一开头——仅夜场/傍晚/夜场为主/夜间街区演艺/多场/全天/日场/场次随排期（这是 app/services/agent/plan.py 里 _show_night_only 分桶契约，前缀错会破坏演出分桶）；参考格式「多场（约14:00/16:30/19:30，以当日公告为准）」「仅夜场（约20:10/21:35两场）」。未经核实的行保持原值不动。
4. 执行 .venv/Scripts/python ops/refresh_show_sessions.py（dry-run 看 diff）→ 确认无误后 --apply 落盘（自动备份 CSV 到 _src/ 并同步 DB）。
5. 汇报：变更行数 + 每行新旧值一行带过；无变化就一句话「本周 50 场次均无变化」。

红线：严禁 git 操作；严禁改动任何代码文件（refresh_show_sessions.py 是数据管线不是代码任务对象）；只走这一个 pipeline；不做其它任何自动化。
