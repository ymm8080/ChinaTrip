# ADR：全程级 CP-SAT 求解 + 披露变量化（2026-11-17 拍板框架；同日修订：P1/P2 旁路新模块无前置即行，48h 静默仅约束 P3 切流）

- 背景：`solver.py` 已是 OR-Tools CP-SAT（单日排期：区间变量/开放窗/NoOverlap/铁律 pin），但地盘只到「单日时刻」。选点、必去绑定、跨天分配、编辑重排都在 `agent/plan.py`（32k 行 / 500 函数）的启发式级联里；降级契约规定 CP-SAT 不可行 → 回退 LLM 自修复链——**恰在最难的输入上丢掉确定性与完备性**。2026-11-17 基线排查实证：13/13 轮披露「求解器未收敛，时间已按顺序兜底排列」、同输入绑定漂移、必去双在场。
- 本文件是**实施前拍板记录**：并行会话正在重构选点/求解器区域（plan.py 持续在改），动它必撞车；收敛前只落运行时不变量（已落）。（2026-11-17 修订：P1/P2 经旁路新模块实施、不触碰 plan.py，无需等收敛；仅 P3 切流需安静窗口，见 D4。）

## D1 目标架构：模型掌管全程，披露变成量

- **变量**：每个候选 POI × 天 → `presence`（optional bool）+ `day` + `start`（区间变量）；每个必去/心愿条目一个 `requested` 字面量 + 一个 `unplaced_var`（bool）。硬链：`requested ∧ ¬presence → unplaced_var`——**必去静默丢失在模型层不可表示**，只能翻转 `unplaced_var` 落进 unplaced/披露（现 e9b492c 出站闸的运行时版）。
- **硬约束**（现 rules.py 铁律的模型化）：开放窗（含 16:00/15:30 白天入场闸，2026-11-17 晚闸口径：SHOW/夜游/夜市豁免、塔类不豁免）、NoOverlap、城际腿缓冲、pinned 时刻、餐锚、班次接驳链。
- **软约束/目标**（字典序分层，替代手搓代价塔 `_morning_extra_cost/_big_first_cost/...`）：①必去覆盖最大化（按重要度加权）②偏好/多样性/评分（补点排序口径同 2026-11-17 拍板：类别精确>距离>时长>评分）③总车程最小化 ④makespan。
- **转移结构/地理邻接（2026-11-17 补）**：距离矩阵（`coords.haversine_m`/通勤估计）+ `access_services` 接驳档案（access/board 分钟、票价）作弧权，日内顺序用环/弧变量表达——「地理相邻」不再是 5km/25km 距离闸硬卡，而是目标③总车程最小化 + 日内转移时间约束；「邻近顶替」属审计语义，留在出站闸。
- **远郊行程腿（2026-11-17 补）**：接驳 access/board 时长=长区间约束（慕田峪类远郊点吃掉大块时间，模型天然不会往远郊日塞市区点）；远郊日专属性=日级聚合约束（当天含远郊簇点→同日其余点须同簇或为空，语义同 `_separate_remote_must_days/_day_already_remote`）；到达/离城端点日=端点约束（行前卡体系同源）。
- **天气条件化（2026-11-17 补）**：天气是输入数据不是模型内部推理——`weather_reports` 预报 × 库内 indoor/rain_ok 属性（`backfill_indoor_rain` 已回填）作 POI×天 条件；雨日户外点降权/禁排（现 `_MUST_RAIN_OUTDOOR_PENALTY/_MUST_RAIN_INDOOR_PENALTY` 代价语义改为软约束/条件约束），`rain_outdoor` 披露由约束事实生成；预报变更=换输入重解，编辑通道现成。
- **松弛阶梯替代 LLM 自修复链**：不可行 → 按 D2 声明顺序逐级放软约束（CP-SAT assumptions 字面量），`sufficient_assumptions_for_infeasibility` 直接产出**不可行证书**（「豫园 16:30 闭园 + 朱家角 15:08 回城」）→ 披露文案由证书生成，LLM 只叙述不修排期。
- **确定性**：固定 `num_workers=1` + 固定搜索种子；同输入同输出（「同输入不同行程」应是红灯测试而非日常）。
- **编辑重排**：改时长/挪天/删卡 → 上一版解作 solution hint 热启动重解，替换 `_ripple_after_duration/_resequence` 手搓顺延梯。

## D2 迁移路径（四段，每段独立可验收）

1. **P0（已落地）**：运行时不变量出站闸——必去三分律审计 e9b492c + 双在场清脏 9630b98 + 契约场景测试（test_plan_contract.py）。任何路径产出的行程都过闸，静默丢失先灭绝。
2. **P1（无前置，旁路开工）**：把「请求 → 候选集 → 排期」抽成显式输入的纯核（request model：musts/wishes/constraints 结构化），LLM 只留意图抽取与叙述；纯核落在**独立新模块**（不 import、不改动 agent/plan.py——输入=会话事实快照，输出=候选行程结构），与并行热改零碰撞，可立即实施；现级联后续作种子（warm start）。
3. **P2（影子运行，零碰撞）**：全程级 CP-SAT 与现级联并行跑，同输入对比（黄金行程语料做裁判）；影子驱动只经现级联的既有入口接口，不改 plan.py；只记录不切流。
4. **P3（切流收口）**：切 CP-SAT 主路径，删级联回退分支；「求解器未收敛」披露归零为验收线；P4 编辑热启动重解替手搓顺延。

## D3 验收与回归

- 契约测试全绿（三分律/双在场/双胞胎口径）+ 黄金行程语料（真实事故场景库，持续扩）+ 属性式不变量（同输入逐字节可复现）。
- 性能：每程几十个景点，CP-SAT 亚秒级；现有 3s 预算不动。
- **防御纵深**：切流后 P0 出站闸（三分律审计/双在场清脏/入场闸读闸/rain_outdoor 披露）保留为运行时不变量验收线——任何生成路径都过闸，不是排期逻辑的重复执行。
- **功能等价契约（P3 硬门槛，2026-11-17 补）**：现行功能对照清单见 `DESIGN/cpsat_feature_parity_2026-11-17.md`——按用户可见能力分 14 域（意图绑定/选点去重/分天/排时闸/餐饮/交通/天气/地理/空档备选/编辑会话/审计披露/演出夜档/酒店预订/运行时），每项标注 现行实现（函数锚点）→模型归宿（硬约束/目标/输入/模型外/退役）→验收锚点（测试文件）；P3 切流前置=清单逐项对齐，任何「现在有、模型无」=阻塞项回 P1 补核。
- 回滚：P2 影子期无风险；P3 保留级联开关一版。

## D4 风险与坑

- 与并行重构的碰撞窗口（2026-11-17 修订，取代原「plan.py 区 48h 无提交才启动」的全局前置）：P1/P2 走旁路新模块，零碰撞、无前置；48h 静默收窄为**仅约束 P3 切流那一次提交**——唯一触碰 agent/plan.py 的入口替换+开关小 diff，仍需 plan.py 选点/求解器区连续 48h 无提交（或与并行会话对齐的安静窗口）再落。理由：48h 是「就地改造 plan.py」路线的协作前置而非技术前置；旁路路线把它从全局等待降级为最后一步的提交窗口。
- LLM 边界：意图抽取（含 schema 校验+确定性兜底，2026-11-17 已建 wish_fast/_parse_site_answer 先例）与叙述；绝不进放置决策。
- 披露文案由证书生成时注意双语（lang 会话字段）。
- CP-SAT 字面量不可行证书对字典序目标的适配：先跑 assumptions 再分层优化，别混在一次求解里。

## D5 pin 溯源契约（2026-11-17 用户拍板「非手动 pinned 可以改时间」）

- 现状缺陷：`pinned` 无「谁钉的」溯源——引擎钉（必去绑定、`_pin_musts_by_importance` 预排时、重开保位硬锚）与用户手动钉同走铁律 19 全钉死（`rules.validate_pinned` 文案自证 "user-confirmed (pinned)"）。e6133a4 已先修最痛一档：pinned+无时刻不再整日判死（「求解器未收敛」披露全勤的根因：绑定层先钉名后钉时的中间态被 solver 按日判死）。
- 新契约：`VisitItem.pin_source: "user" | "engine" | None`：
  - **user**：铁律 19 照旧——时刻神圣，不可移/改/删；
  - **engine**：「必在」保证（不可静默消失，归 P0 覆盖审计三分律管），**时刻完全可重排**——生成期重要度预排时降为 warm-start hint（软偏好/目标项），不再硬窗；编辑/顺延/重排时随盘面浮动；
  - **None**（存量兼容）：保守按 user 处理（保护既有用户钉），新代码路径一律显式落 source。
- `validate_pinned` 只对 user 溯源执行铁律 19；engine 钉由三分律/覆盖不变量守护（已排 | unplaced | 披露）。
- 重开保位（b909d60 硬锚语义）改由「初始时刻 hint」承载——稳定性来自提示与目标函数，不来自刚性约束。
- 实施归属：**P1 request model 的核心字段**（用户→求解器的意图边界），随纯核一起落；全程级模型的 `requested` 字面量天然承载 engine 语义（presence 硬约束 + start 自由变量）。
